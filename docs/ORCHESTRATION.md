# Оркестрация агентов

Как раздавать задачи, в каком порядке и где нужен человек. Инструмент любой: Claude Code с сабагентами, OpenCode, Kilo Code или несколько сессий вручную. Схема одна.

## Роли

| Роль | Кто | Что делает |
| --- | --- | --- |
| Владелец | Никита | Утверждает контракты, проходит гейты, тестирует в зале |
| Оркестратор | Один агент на весь проект | Выдаёт задачи по волнам, мержит, единственный правит `project.yml` и `docs/SPEC.md` |
| Исполнитель | Новый агент на каждую задачу | Делает ровно одну задачу в своей ветке и worktree |
| Ревьюер | Новый агент, не видевший работу исполнителя | Проверяет ветку задачи против критериев приёмки и `AGENTS.md`, ничего не правит |

Ревьюер всегда свежий: агент, который писал код, свою работу не принимает.

## Волны

```
Волна 0   T00 каркас и контракты
            │
          ──┴── Гейт G0: владелец утверждает контракты
            │
Волна 1   T01 Storage   T02 Справочник   T03 Engine   T04 DesignSystem   T05 Intents
            │
Волна 2   T06 Session   T07 Live Activity   T08 Экран тренировки   T09 Программа   T10 История
            │
Волна 3   T11 Сегодня и сборка приложения   T12 CSV   T13 Fastlane и CI
            │
          ──┴── Гейт G1: первая тренировка в зале
            │
Волна 4   T14 Интеграция и полировка
            │
          ──┴── Гейт G2: TestFlight
```

Задачи внутри волны независимы и идут параллельно. Точные зависимости в поле «Зависит от» каждой задачи: если зависимости смержены раньше волны, задачу можно стартовать раньше.

| --- | --- | --- |
| T00 | нет | всё |
| T01 | T00 | Core/Storage |
| T02 | T00 | Core/Storage (только ресурсы и `ExerciseSeed`) |
| T03 | T00 | Core/WorkoutEngine |
| T04 | T00 | UI/DesignSystem |
| T05 | T00 | UI/Intents |
| T06 | T01, T03, T05 | UI/Session |
| T07 | T04, T05 | UI/LiveActivityShared, LiftWidgets |

## Гейты

**G0, после T00.** Владелец читает публичные интерфейсы в коде и `project.yml`. Всё, что не так в контрактах, правится сейчас. После G0 контракты заморожены, изменения только через `docs/proposals/`.

**G1, после волны 3.** Сборка на свой iPhone, одна реальная тренировка. Владелец пишет заметки в `docs/gym-notes/<дата>.md`. Из них оркестратор формирует подзадачи для T14.

**G2, после T14.** Владелец проверяет чек-лист T14 и сам загружает билд в TestFlight через `fastlane beta`.

## Цикл одной задачи

1. Оркестратор создаёт ветку `task/T03` и worktree, запускает исполнителя с промптом ниже.
2. Исполнитель делает задачу, прогоняет команды из `AGENTS.md`, коммитит в свою ветку и возвращает отчёт.
3. Оркестратор запускает ревьюера с промптом ниже.
4. Ревьюер возвращает `APPROVE` или список замечаний с файлом и строкой.
5. Замечания уходят тому же исполнителю, максимум 2 круга. Третий круг значит, что задача плохо поставлена: оркестратор переписывает файл задачи и запускает нового исполнителя.
6. Мерж в `main` только при `APPROVE` и зелёных тестах. Rebase, не merge-коммиты.

## Промпт исполнителя

```
Ты исполнитель задачи {TASK_ID} в репозитории дневника тренировок.

1. Прочитай AGENTS.md в корне.
2. Прочитай docs/tasks/{TASK_ID}.md целиком.
3. Прочитай разделы docs/SPEC.md, на которые ссылается задача, и AGENTS.md модулей, которые будешь трогать.
4. Сделай задачу. Меняй только файлы из раздела «Файлы».
5. Прогони команды из раздела «Проверка» задачи. Все должны быть зелёными.
6. Закоммить в свою ветку. Верни отчёт: чек-лист критериев приёмки, у каждого пункта тест, превью или файл из docs/evidence/{TASK_ID}/.

Если контракт из SPEC мешает, не обходи его: опиши проблему в docs/proposals/{TASK_ID}.md и остановись.
```

## Промпт ревьюера

```
Ты ревьюер задачи {TASK_ID}, ветка task/{TASK_ID}. Код не правишь, только проверяешь.

1. Прочитай AGENTS.md, docs/tasks/{TASK_ID}.md и разделы docs/SPEC.md из задачи.
2. Посмотри дифф: git diff main...task/{TASK_ID}.
3. Проверь каждый критерий приёмки: выполнен ли и чем доказан. Сам запусти тесты.
4. Проверь правила AGENTS.md: границы файлов, контракты не изменены, нет force unwrap, магических чисел, захардкоженных строк, print, мёртвого кода.
5. Проверь тесты: покрывают ли они правила из SPEC, а не только счастливый путь.

Ответ: первой строкой APPROVE или CHANGES. Дальше замечания списком: файл:строка, что не так, что ожидается.
Не придирайся к вкусовщине, которой нет в AGENTS.md.
```
