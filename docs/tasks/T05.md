# T05: Intents

- **Волна:** 1
- **Зависит от:** T00
- **Блокирует:** T06, T07
- **SPEC:** разделы 4 (важные решения, п. 1), 6.5

## Цель

Интенты, которые вызываются из кнопок Live Activity, кнопки Action и Siri. Они ничего не знают про движок и только передают команду зарегистрированному обработчику.

## Файлы

- `Packages/UI/Sources/Intents/**`
- `Packages/UI/Tests/IntentsTests/**`

## Что сделать

1. `SessionCommandRegistry` и протокол `SessionCommandHandler` по SPEC 6.5.
2. `AdjustmentKind: AppEnum` с четырьмя кейсами и русскими `caseDisplayRepresentations`: «Прибавить вес», «Убавить вес», «Добавить повтор», «Убрать повтор». Маппинг в `Adjustment` из `Domain`.
3. `LogSetIntent`, `AdjustSetIntent`, `SkipRestIntent` как `LiveActivityIntent`. `openAppWhenRun = false`. `perform()` достаёт обработчик из реестра и вызывает `perform(_:source:)`. Источник: `.liveActivity` по умолчанию, у `LogSetIntent` из Shortcuts `.shortcut` (отдельный параметр или отдельная обёртка `LogSetShortcutIntent`, на выбор исполнителя, решение описать в `AGENTS.md` модуля).
4. Нет обработчика: результат с диалогом «Тренировка не начата», без ошибки.
5. `LiftShortcuts: AppShortcutsProvider` с `LogSetIntent` и фразами «Подход сделан в \(.applicationName)», «Записать подход в \(.applicationName)». Иконка `checkmark.circle`.
6. Все строки через String Catalog.

## Критерии приёмки

- [ ] Тест: каждый интент с фейковым обработчиком в реестре вызывает ровно одну нужную команду с нужным источником.
- [ ] Тест: без обработчика интент не падает и возвращает результат.
- [ ] Тест: `AdjustmentKind` взаимно однозначно маппится в `Adjustment`.
- [ ] Модуль зависит только от `Domain`, `AppIntents`, `Foundation`. Нет импорта `WorkoutEngine`, `Session`, `ActivityKit`.
- [ ] В README модуля (его `AGENTS.md`) описано, как назначить интент на кнопку Action: Настройки, Кнопка действия, Быстрая команда, «Подход сделан».

## Не делать

- Не хранить состояние в интентах.
- Не открывать приложение из интентов.
