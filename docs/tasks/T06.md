# T06: Session

- **Волна:** 2
- **Зависит от:** T01, T03, T05
- **Блокирует:** T08, T11
- **SPEC:** разделы 4 (важные решения), 6.3 (`ContentState`), 6.4

## Цель

Слой между движком и всем остальным: UI, Live Activity, уведомления, интенты. Экраны и интенты говорят только с `SessionCoordinator`.

## Файлы

- `Packages/UI/Sources/Session/**`
- `Packages/UI/Tests/SessionTests/**`

## Что сделать

1. `SessionCoordinator` по SPEC 6.4, реализует `SessionCommandHandler`.
2. Каждая команда: вызов движка → новый `snapshot` → `ActivityPresenter.update` → перепланировать `RestNotifier`. `LiveActivityPresenter` при обновлении ставит `staleDate = restEndsAt`, чтобы Live Activity сама вернула кнопку «Готово», когда отдых кончится. Ошибки движка кладутся в `lastError`, наружу не летят.
3. `perform` без загруженной сессии сначала вызывает `restore()`. Это важно: интент из Live Activity может поднять приложение из фона с пустой памятью.
4. `start(dayID:)`: движок → `ActivityPresenter.start`. `finish()`: движок → `ActivityPresenter.end` с `isFinished = true` → `RestNotifier.cancel`. `discard()`: то же, но через `engine.discard()`, тренировка в историю не попадает.
5. Счётчик действий по SPEC 6.4. Открытие приложения и навигация не считаются, только команды.
6. `LiveActivityPresenter: ActivityPresenter` на ActivityKit. Если Live Activities выключены пользователем, молча ничего не делает. Хранит текущую `Activity`, при `restore()` находит уже идущую через `Activity<WorkoutActivityAttributes>.activities`, а не создаёт вторую.
7. `LocalRestNotifier: RestNotifier` на `UNUserNotificationCenter`: одно уведомление «Отдых закончился», в тексте упражнение и следующий подход. Идентификатор постоянный, новое уведомление заменяет старое. Запрос разрешения при первом `start`.
8. Моки `ActivityPresenter` и `RestNotifier` для тестов и превью, публичные под `#if DEBUG`.

## Критерии приёмки

- [ ] Тест: каждая `SessionCommand` вызывает нужный метод движка и один `update` презентера с `ContentState`, соответствующим снапшоту.
- [ ] Тест: `logSet` ставит уведомление на `restEndsAt`; `skipRest` и `finish` его отменяют; последний подход тренировки уведомление не ставит.
- [ ] Тест: счётчик действий. Сценарий `adjust`, `adjust`, `logSet` передаёт в движок `inputActions == 3`, следующий `logSet` без шагов передаёт 1.
- [ ] Тест: `perform` на свежем координаторе с активной тренировкой в репозитории восстанавливает сессию и выполняет команду.
- [ ] Тест: ошибка движка попадает в `lastError`, `snapshot` не портится.
- [ ] Маппинг `ContentState(_ snapshot:)` из SPEC 6.3 реализован здесь и покрыт тестом: обычный подход, отдых, конец тренировки.

- Не дублировать правила движка. Координатор не считает вес и не решает, какой подход следующий.
