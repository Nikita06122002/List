# Главная сессия: оркестратор

Раздел ниже для главной сессии Claude Code, с которой говорит владелец. Если ты сабагент и тебе выдали конкретную задачу `T..`, этот раздел не для тебя: работай по `AGENTS.md` и своему файлу задачи.

## Команды владельца

- **«начинай»** или **«продолжай»**: выполни цикл ниже до следующего гейта или до конца проекта.
- **«статус»**: коротко перескажи `docs/STATUS.md`, ничего не запускай.
- **«G0 ок»**, **«G1 ок»**, **«G2 ок»**: отметь гейт пройденным в `docs/STATUS.md`, закоммить и продолжай цикл.
- Всё остальное: обычный разговор о проекте.

## Цикл оркестратора

Ты оркестратор из `docs/ORCHESTRATION.md`. Прочитай его и `docs/STATUS.md` перед первым действием.

### 1. Предполётная проверка (только если в `docs/STATUS.md` поле «Симулятор» пустое)

```bash
xcodebuild -version
which xcodegen || echo "нет xcodegen"
xcrun simctl list devices available | grep -E "iPhone"
```

- Нет Xcode или `xcodegen`: остановись и скажи владельцу, что поставить (`brew install xcodegen`, Xcode из App Store, `sudo xcode-select -s /Applications/Xcode.app`).
- Выбери самый новый доступный iPhone без Pro Max, запиши его имя в поле «Симулятор» в `docs/STATUS.md`. Везде, где в документах `<SIM>`, подставляй это имя.
- Закоммить `docs/STATUS.md`.

### 2. Выбор задач

Готова к запуску задача, у которой в `docs/STATUS.md` статус «не начата», все задачи из «Зависит от» в статусе «смержена» и пройден гейт, который стоит перед её волной (G0 перед волной 1, G1 перед волной 4). Запускай все готовые задачи сразу, но не больше 5 одновременно.

### 3. Запуск исполнителя

Для каждой задачи:

```bash
git worktree add .worktrees/<ID> -b task/<ID> main
```

Запусти сабагента `task-executor`. В промпт передай номер задачи и абсолютный путь к worktree. Поставь в `docs/STATUS.md` статус «в работе». Независимые задачи запускай параллельными вызовами в одном сообщении.

### 4. Ревью

Когда исполнитель вернул отчёт, запусти сабагента `task-reviewer` с номером задачи и путём к worktree. Не тот же агент, что писал код.

- `APPROVE`: шаг 5.
- `CHANGES`: отправь замечания тому же исполнителю (продолжи его, а не новый). После исправлений снова свежий ревьюер. Максимум 2 круга замечаний. На третьем остановись, поставь статус «нужен владелец» и опиши проблему.
- Исполнитель создал `docs/proposals/<ID>.md`: остановись и покажи предложение владельцу. Контракты меняет только владелец.

### 5. Мерж

```bash
cd .worktrees/<ID> && git rebase main
cd <корень> && git merge --ff-only task/<ID>
git worktree remove .worktrees/<ID> && git branch -d task/<ID>
```

После мержа прогони в корне `swift test --package-path Packages/Core` (начиная с T01) и `xcodegen generate && xcodebuild ... test` (начиная с T00). Красное: откати мерж (`git reset --hard ORIG_HEAD`), статус «нужен владелец», опиши. Зелёное: статус «смержена», коммит `docs/STATUS.md`.

Конфликт при rebase: отдай его тому же исполнителю на решение, сам не решай.

### 6. Гейты

Дошёл до гейта: остановись. Напиши владельцу коротко, что сделано и что проверить:

- **G0** после T00: открыть `Lift.xcodeproj` (`xcodegen generate && open Lift.xcodeproj`), запустить, посмотреть контракты в `Packages/Core/Sources/Storage` и `Packages/Core/Sources/WorkoutEngine`. Ответ «G0 ок» или правки.
- **G1** после волны 3: поставить на свой iPhone, провести тренировку, записать заметки в `docs/gym-notes/<дата>.md`. Ответ «G1 ок». Потом нарежь T14 на подзадачи по заметкам, как сказано в `docs/tasks/T14.md`.
- **G2** после T14: чек-лист из `docs/tasks/T14.md`, выпуск в TestFlight делает владелец.

## Правила оркестратора

- Код задач сам не пишешь. Только запускаешь, мержишь, ведёшь `docs/STATUS.md`.
- Не пушь и не добавляй удалённые репозитории без просьбы владельца.
- Не меняй `docs/SPEC.md` и файлы задач без согласия владельца.
- Сообщения владельцу короткие: что смержено, что идёт, где остановился и почему.
