# AGENTS.md

Правила для любого ИИ-агента, который работает в этом репозитории. Читай целиком перед первой правкой.

## Что за проект

Нативный iOS-дневник силовых тренировок. Одна цель: подход записывается за 1-2 действия, чаще всего без разблокировки телефона. Продуктовые решения, архитектура и контракты модулей лежат в `docs/SPEC.md`. Порядок работы агентов в `docs/ORCHESTRATION.md`. Твоя конкретная задача лежит в `docs/tasks/`.

## Перед началом задачи

1. Прочитай свой файл задачи в `docs/tasks/` полностью.
2. Прочитай разделы `docs/SPEC.md`, на которые он ссылается.
3. Прочитай `AGENTS.md` каждого модуля, который будешь трогать (`Packages/<Package>/Sources/<Module>/AGENTS.md`).
4. Проверь, что задачи из поля «Зависит от» смержены. Если нет, остановись и сообщи оркестратору.

## Границы

- Меняешь только файлы из раздела «Файлы» своей задачи, плюс всегда можно `docs/evidence/<TASK_ID>/` и `docs/proposals/<TASK_ID>.md`. Нужно тронуть что-то ещё: остановись и опиши, что и зачем. `docs/STATUS.md` ведёт только оркестратор.
- Публичные контракты из `docs/SPEC.md` раздел 6 не меняешь. Если контракт мешает, пиши предложение изменения в `docs/proposals/<task-id>.md` и останавливайся.
- Сторонние зависимости не добавляешь. Только Apple SDK.
- `project.yml` меняет только T00 и оркестратор. `.xcodeproj` не коммитим, он генерируется.

## Стек и стиль

- Swift 6, strict concurrency `complete`. Никаких `@unchecked Sendable` и `nonisolated(unsafe)` без комментария, почему иначе нельзя.
- iOS 17.0 минимум. SwiftUI для всего UI, UIKit не используем.
- SwiftData для хранения. Доступ к `ModelContext` только внутри модуля `Storage`.
- `@Observable` вместо `ObservableObject`.
- Без force unwrap и `try!` вне тестов.
- Без магических чисел в отступах и размерах: только токены из `DesignSystem` (`Spacing`, `Radius`, `FontStyle`).
- Строки интерфейса через String Catalog (`Localizable.xcstrings`), язык по умолчанию русский. Захардкоженный текст во вьюхе считается ошибкой.
- Вес в доменной модели всегда `Decimal` в килограммах. Форматирование только через `WeightFormatter` из `DesignSystem`.
- Мёртвый код, закомментированный код и `print` не оставляем.

## Тесты

- Swift Testing: `import Testing`, `@Suite`, `@Test`, `#expect`. XCTest не используем.
- Модули `Domain`, `Storage`, `WorkoutEngine` тестируются через `swift test` на macOS, без симулятора. Поэтому в них нельзя импортировать UIKit, ActivityKit, WidgetKit.
- Логика без тестов не принимается. UI тестами не покрываем, вместо этого SwiftUI Preview на каждый экран и компонент.

## Команды

```bash
# сгенерировать проект
xcodegen generate

# тесты пакетов, быстро
swift test --package-path Packages/Core

# <SIM> это имя симулятора из docs/STATUS.md

# сборка приложения и расширения
xcodebuild -scheme Lift -destination 'platform=iOS Simulator,name=<SIM>' build

# все тесты
xcodebuild -scheme Lift -destination 'platform=iOS Simulator,name=<SIM>' test
```

## Готово значит

- [ ] Проект собирается без новых предупреждений.
- [ ] `swift test` и `xcodebuild test` зелёные.
- [ ] Все критерии приёмки из файла задачи выполнены, по каждому есть доказательство: тест, превью или скриншот.
- [ ] Обновлён `AGENTS.md` затронутого модуля, если поменялось что-то, что должен знать следующий агент.
- [ ] Один логический коммит на задачу, сообщение `T07: Live Activity с кнопками шага`.
- [ ] В финальном отчёте чек-лист критериев приёмки с отметками.

Репозиторий локальный, без удалённого сервера и PR. Где в задаче написано «в PR», это значит «в финальном отчёте исполнителя». Скриншоты и видео кладутся в `docs/evidence/<TASK_ID>/`: `xcrun simctl io booted screenshot <файл>.png`, `xcrun simctl io booted recordVideo <файл>.mp4`.

## Если застрял

Не угадывай. Три неудачные попытки починить одну и ту же ошибку значат стоп: опиши, что пробовал и что видишь, и верни задачу оркестратору.
